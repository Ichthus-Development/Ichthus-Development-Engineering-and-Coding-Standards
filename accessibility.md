# Accessibility Standards

> **Policy status:** Initial scope. A governing conformance target and normative requirements have not yet been adopted.

Accessibility is an engineering responsibility independent of any particular UI framework. Public-facing software must account for people with differing visual, auditory, motor, cognitive, speech, and neurological abilities.

## Terminology

Use common language alongside technical terminology where it improves precision, including:

- Color blindness / color vision deficiency
- Protanopia, deuteranopia, tritanopia, and achromatopsia
- Blindness / total vision loss
- Low vision / partial vision loss
- Deafness and hard of hearing
- Limited mobility / motor impairment

Future revisions should address perceivable information, keyboard and alternative input, focus, navigation, color, contrast, text scaling, reflow, non-text content, captions, forms, errors, motion, timing, assistive-technology semantics, testing, and documented exceptions.

Accessibility requirements complement, but are not replaced by, [User Interface Standards](ui-standards.md).
